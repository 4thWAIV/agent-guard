Stage inputs and outputs: reader, information and purpose

Files supplied from outside a stage appear under Entering this stage. Results produced and read inside it appear under Internal handoffs. Both kinds of reads count in the usage matrix.

Existing scripts and the replacement design are separate views. The script view traces named prompts and return objects. The design view shows specified relationships and marks proposed bindings with “?”. Neither is an observed file-access log.

Identifiers label artifact roles, not invented filenames. A role may produce multiple files per agent run. Source-code rows can select the same physical files at different revisions; they must not be added together to claim a physical-file total.

The new file flow is not fully specified. DESIGN’s assignment does not pin the task requirements; most later stages lack new assignment/result types; REVIEW has no defined work. These gaps stay visible rather than becoming invented inputs. No workflow policy or type is changed by this map.

Artifacts to question—not automatic deletion candidates

  • GR-evidence-view: only a collective label. The saved evidence has its own rows; another umbrella evidence file would duplicate their indexing.
  • GR-ledger: contains references, not findings. It has consumers. The remaining value question is whether its grouping of search/evaluation pairs is needed separately from Workflow’s assignments and results.
  • DS-reviews: the working design calls for separate enabled reviews, but their replacement input/output arrangement is unfinished. The existing DESIGN script already returns a judge verdict. Do not assume the two are interchangeable or create a second verdict summary.
  • AR-result: carries an architecture determination and is used for review/handoff. Its signature description and build proof must not become competing copies of source files and tool captures. The replacement fields are not settled.
  • RL-results / TS-results versus captures: a case/coverage mapping and a captured command response serve different purposes. Their replacement schemas must establish that separation; a second transcript adds no evidence.
  • GT-captures: the existing skill requires closing verification. Whether the replacement can reuse earlier valid evidence is not defined. A copied transcript would not be new evidence.
  • RT-report → REVIEW: the report presents the outcome to the human. REVIEW’s additional responsibility is unresolved; its proposed inputs do not prove that a separate processing step is useful.
