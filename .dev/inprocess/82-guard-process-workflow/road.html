The architecture language: where it stands

The architecture language is ts/metalang/arch.yaml, a document written in MetaLang. Its job is to let a project write down what its code is made of, so a person can read it and sign it, and so it can be checked back against the real source in C#, Python, Rust and TypeScript. Each step on the road is one sentence the language gains the power to write. Read against the code on 25 October 2026.

What steps 2 to 5 are written as

Each element is its own declaration

An element of an architecture is written with MetaLang's constant, under the name the thing actually has. The name it is known by is the name it is declared under, so nothing carries two names.

  - constant:
      id: IGuard
      is: element
      value:
        form: interface
        does: The three behaviours every guard answers a tool call through.

That needed two keywords on constant, which could name a fixed value and say nothing about it: is, the type its value is of, and value, the value itself. Both are required — a constant that does not say what its value is of cannot be checked, and a constant with no value is a name standing for nothing. Two documents are written this way: ts/metalang/parts.yaml, the six parts of the toolchain, and handoff/guard.yaml, the five parts of the guard.

And what it is made of

kind and kinds declare the five kinds a member may be — method, constructor, property, field and value — each with the mark it is drawn with, a real example from this repository and one line saying what it is. member is one named piece of an element, and carries its own name because a member is not declared and so has no id to be known by. members holds them as a list, in the order the source declares them.

  - constant:
      id: IGuard
      is: element
      value:
        form: interface
        does: The three behaviours every guard answers a tool call through.
        members:
          - name: PrecheckAsync
            kind: method
            does: Judges a tool call before it runs.

A kind that is not one of the five is reported at the kind, with the five listed. A member missing its name or its kind is reported at the member. A word a member does not carry is reported at the word. The same member written twice is reported, because a list's entries are unique. handoff/guard.yaml names the members of all five parts of the guard, each one read out of the source before it was written.

And where it sits

The three kinds of place are a closed vocabulary of this language, beside the six forms and the five kinds of member. Each carries its own mark, a real example, the name it is shown by and one line saying what it is. sits holds one line for each of them, and a level the language has no word for says none.

  - constant:
      id: IGuard
      is: element
      value:
        sits:
          package: none
          assembly: AgentGuard.Abstractions
          namespace: AgentGuard.Abstractions.Contracts
        form: interface
        does: The three behaviours every guard answers a tool call through.

Writing it keyed by the vocabulary needed one new word in MetaLang — map, one of a thing for each word of a closed set. Every word that set lists is written, a key it does not list is refused against the words it does, and a word that holds nothing says so with a reserved state. role gained a fourth member, mark, so a page reaches the glyph the way it already reaches the kind, the prose and the name. On a card, each line is drawn in its own colour and stepped in one place from the line above, so the order reads as what contains what.

And what it stands to

The three ways one element can stand to another are a closed vocabulary of this language, as the forms, the kinds of member and the kinds of place are. relates holds one line for each, and each line names the elements it stands to that way.

  - constant:
      id: FileGuard
      is: element
      value:
        relates:
          implements: [IGuard]
          answers: [Verdict]
          holds: none

It is written with MetaLang's link: a value written as the id of a declaration, with to naming the type that declaration must carry a value of. A name nothing the document reaches declares is refused where it is written, so a relation can never point at nothing, and the page draws each name as the same reference chip every other reference uses.

The direction this replaced, and why it was declined

Declaring the six forms as six kinds a document writes was built, measured and declined. Adding the kinds at all required the architecture language to re-declare MetaLang's own declaration choice and replace its list. A kind named enum took MetaLang's enum away from every document written in the language, which left ts/metalang/names.yaml — whose languages and equivalents are enums — unwritable. And it left the file a part lives in and the glyph it is drawn with nowhere to live. Measured against each other: 115 of the tests failing, against 4 for the shape that was taken.

Where this fits

The architecture language is the tool. Issue 82's workflow is the subject: eight phases — Design, Spec, Rule, Test, Implement, Refute, Gate, Report — of which one is designed and seven are names, with nothing in its contract signable because every decision in it is still proposed. The language has to be able to say what a thing is made of and how two things relate before a rule or a test can be written about anything, which is why the road comes first.
