Guard operations

OperationSurfaceStatusWrites
guard workflow open Creates the identity and the empty documents. Refuses a second folder for the same work item. CLI & MCP proposed Workflow, Conversation, the work folder, and the GitHub issue when none exists
guard conversation set Section-scoped. Neither editing style grants whole-file writes, and a section the current phase may not touch is refused. CLI & MCP proposed One named Conversation section
guard gate request Guard renders the content from the saved sections and hashes those exact bytes with their source versions. No agent composes it. CLI & MCP proposed Nothing. Returns the rendered request and its hash
guard gate sign Takes the signed outcome against the request hash, with the presence result. A checkpoint is written only for Approve. CLI & MCP proposed Checkpoint, and the fields that gate locks
guard observation write Guard computes or runs the thing itself and keeps the result — the diff from the repository, or a command with its output and exit code. No agent supplies an observation. CLI & MCP proposed Any change-record field
guard result submit Validates the submitted result's structure and references before storing it. An invalid submission is not marked completed. CLI & MCP proposed The agent result file, and its reference in Workflow
the PreToolUse and PostToolUse hook The shipped guard. An ordinary working-tree edit goes through it, not through a workflow operation. hook exists Nothing in the workflow. Guards ordinary file edits

Conversation

The predecessor of the Contract, and the only document that exists at every level. Where both hold the same concept, Conversation carries the proposal and the Contract carries the proven version with the extra L1 and L2 sections on top. At L3 there is no Contract, so these fields are the governing requirement. Holds the wording the human approved, never a transcript of the human.
